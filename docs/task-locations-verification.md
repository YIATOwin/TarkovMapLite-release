# 商人任务坐标检查（2026-11-16）

## 缺口与处理

旧内置数据共 499 个商人任务，只有 176 个带区域。初次导入补充快照时只保存筛选元数据，没有导入其中的目标坐标；因此邮递员、背景调查、医疗隐私、化学品等任务可以按地区查询，却没有可画的取物点。另外，仅进行中开关会挡住显式选中的未记录／完成／失败任务，造成有区域也看不到。

固定来源为 2026-09-14 的公开快照：
https://github.com/sayser/TarkovTracker/blob/f4ad6a50be49bbba3c3791fd52aa042d99ce3cfd/tools/data/tarkov_tasks_raw.json

原文件有 927 条目标位置，去重后 868 条。隔离 1 条矛盾记录后，Assets/task-locations.json 保存 867 条位置，保留任务 ID、目标 ID、地图、目标类型与 x/y/z。共 243 个来源任务；仅对当前任务目录中的任务与已收录底图生效，不恢复来源中已下架的任务。

应用到当前内置数据后：

| 项目 | 数量 |
|---|---:|
| 原有区域 | 580 |
| 新增点位／区域 | 354 |
| 修复涉及任务 | 108 |
| 原先完全无坐标、现在可显示 | 56 |
| 原有部分区域、现在补齐 | 52 |
| 合并后带坐标的任务 | 232 |

最初发现 57 个完全没有区域、但来源有坐标的任务；其中 1 个仅涉及破冰船，当前没有该底图，不作错误替代。其余无坐标任务中包含交付、成长和交易目标，不能据此推断全部缺失。

## 合并与优先级

- 在线解析兼容目标／区域的数组、单对象及字典，地图 ID／名称／对象，outline、position 和扁平 x/y/z；不以缺失坐标默认生成 (0,0)。
- 当前接口的同目标、同地图几何优先；旧快照仅补缺口。有当前目标 ID 时，不恢复已移除的目标。
- 旧缓存没有目标 ID 时按任务、地图、目标类型和区域覆盖匹配，保留原始多边形；新增点位之间按真实位置去重，不用显示半径吞掉邻近候选点。
- 点坐标以小方形足迹表示，半径 4 米仅用于显示，不宣称上游给出了这个目标区域范围。高度通过现有建筑范围规则判断楼层，没有规则时保持楼层未知。
- 原区域没有世界高度、且中心与可靠来源点相差不足 1 米时，补回高度并重算语义楼层，保留原轮廓；例如油料快车的海关油罐车恢复地面，避免沿用旧种子的通用高度猜层。
- 在加载旧缓存和在线数据时同样合并，无需玩家清缓存。缓存格式为 schema 14，文件名仍为 data-v8.json。
- 电脑与手机的显式选中预览绕过状态过滤；取消选中立即恢复。搜索不切地图，原图层和手动隐藏设置不变。

## 异常快照

“油料快车”目标文字明确要求标记海关油罐车，原区域与同一快照均有海关位置 (-334.93, 2.22, -163.46)；快照另有同一 x/z、标为储备站、高度 -101.46 的矛盾记录，甚至超出储备站 SVG 图幅。该条放入 excluded，未导入地图；保留四个海关区域。只纠正这个固定日期快照的 reserve 地区标签，不覆盖未来接口数据的地区。

## 验证方式

`dotnet run --project tests/FloorRegression -c Release -- --locations-only <output>` 审计当前任务目录对应的全部有效来源点、所有底图版本的投影与图幅范围、原始多边形保留、重复合并、旧缓存、当前目标优先、异常快照隔离、地图 ID、昼夜和真实高度，并实际绘制邮递员工厂点位。

输出包括 task-locations-audit.json（499 个任务的前后数量与地区）、postman-factory.png、locations-state.json。完整回归还覆盖楼层、地图菜单、任务筛选、主线任务、偏好与自动更新。

`node tests/mobile/task-locations.cjs <output>` 使用真实电脑快照检查邮递员目标、楼层、选中任务的未记录／完成／失败状态、取消选中与多点连线。手机筛选和主线专项继续运行，确保原功能不受影响。

UI-SPEC 走查：没有增加控件或视觉样式；只调整既有任务选中的地图反馈，沿用原状态色、楼层与点位绘制。查询、图层、进度和手动隐藏状态保持独立。

本次本地完整回归通过 5629 项，其中坐标专项 4528 项；手机端坐标专项 6 项、筛选专项 22 项、主线专项 16 项均通过。覆盖 25 张地图、88 个原生楼层视图；构建保留原有 3 条可空性警告，无新增警告。

## 应用图标

Assets/app.svg 为折叠地图、路线起点与导航箭头的可编辑矢量源。`tools/build-app-icon.cjs` 生成 app.png 与含 16／20／24／32／40／48／64／128／256px 的 app.ico；仅开发生成时需要 Playwright，运行程序没有新增依赖。16～24px 隐藏细路线，已查看深浅背景下的尺寸预览。csproj ApplicationIcon 用于 exe 资源，主窗口和更新窗口从同一 ICO 加载，随主窗口释放。
