# UI 规范（TarkovMapLite）

这份文件是**界面写作准则**，不是建议清单。

来源：`b-end-design-system` skill（B 端设计系统执行引擎）里的规范层，被我抽离成**与框架无关**的规则，
再映射到本项目的两个技术栈（手机端 CSS / 电脑端 WinForms GDI+）。
skill 自带的 React + Tailwind 模板代码本项目用不上，规则照用。

**硬性优先级**：本文件 > 手感 > 个人偏好。改界面之前先读对应章节，改完按 §12 走查。
新增颜色 / 圆角 / 字号时，**先加进 §2 的 token 表，再写进代码**；两处必须同时改（见 §13）。

## 1. 适用范围

| 界面 | 是否受本规范约束 |
|---|---|
| 顶栏、侧栏、任务列表、目标/物品面板、状态栏 | ✅ 完全约束 |
| 手机端 chip、按钮、抽屉、toast、任务列表 | ✅ 完全约束 |
| 对话框（手机端二维码窗、确认框） | ✅ 完全约束 |
| **地图画布本身**（底图、任务区域、点位、连线） | ❌ 例外：这是游戏美术，颜色由数据和地图素材决定 |
| 地图上的文字标签、玩家箭头 | ⚠️ 半约束：字号层级和对比度要遵守，配色服从可读性 |

**为什么例外**：规范假设浅色后台页面；我们是暗色地图工具。规范里"页面默认平 / 单一强调色 / 4 档字号"
这些**规则**照用，"暖灰 / 白底卡片"这些**具体值**换成我们的暗色 token。

## 2. 色彩

### 2.1 分三层，业务代码只用第二层

1. **物理色值**：`#0d0f11`、`#4c9aff` —— 只允许出现在 :root 变量定义 / C# 常量类里
2. **语义 token**：`--back`、`--accent`、`--state-warn` —— 业务代码只准用这一层
3. **组件级**：某组件独有的覆写，默认引用语义 token

### 2.2 暗色中性色必须带倾向，不能用纯黑纯灰

人眼看纯 `#000` + 白字会发胖、字距发虚。中性色统一掺 **2%–4% 的冷蓝**（贴近 `--accent`），
让文字、面板、主色是一家人。现有 `--back: #0d0f11` 已经是这个思路，新增灰色请照这个方向配。

### 2.3 现有 token（改值只改这里）

```css
:root {
  /* 表面 */
  --back:   #0d0f11;              /* 画布底 */
  --panel:  rgba(20,23,27,.92);   /* 面板/抽屉 */
  --raised: #171b20;              /* 面板内再抬一层（表格行、chip 底） */

  /* 线 */
  --line:        #2c3138;         /* 标准边框 */
  --line-subtle: rgba(226,232,240,.14);  /* 0.5px 微边框：分割线专用 */

  /* 文字 */
  --text:     #e8eef5;            /* 主文字 */
  --dim:      #96a0ac;            /* 次要：表头、说明、坐标 */
  --text-3:   #6b7480;            /* 三级：占位符、禁用 */

  /* 强调色：全屏只准一个 */
  --accent: #4c9aff;

  /* 状态色：只在表达状态时出现，不当装饰 */
  --ok:    #78c88c;               /* 成功 / 已完成 / 可撤离 */
  --warn:  #e0a458;               /* 预警 / 需钥匙 / 电量类 */
  --danger:#dc6e6e;               /* 失败 / 危险区 */
  --info:  #be96f5;               /* 中性信息（转移点） */
}
```

### 2.4 三条禁令

- **徽章/标签禁止彩虹配色**：状态标签用 `浅底 + 深字`（暗色下是 `半透明状态色底 + 同色系亮字`），
  并且**必须带业务文案**（写"已完成"，不是只有一个小绿点）
- **禁止渐变标题、标题内单词突兀着色**（典型 AI 模板味）
- **除 `--accent` 外，同一屏不出现第二个饱和色**；状态色只在真有状态时出现

## 3. 边框与圆角

### 3.1 0.5px 微边框（三个技术栈的落地法）

拒绝 `1px solid #ccc` 那种上世纪表格感。**分割线一律用半透明**，让底色透上来：

| 栈 | 写法 |
|---|---|
| CSS | `border: 1px solid var(--line-subtle)`（`.14` 透明度等价于高清屏 0.5px 观感） |
| CSS 物理 0.5px | `::after` + `height:1px; transform: scaleY(.5)` |
| WinForms GDI+ | `new Pen(Color.FromArgb(38, 226, 232, 240), 1f)` —— **alpha 是 0.5px 观感的唯一办法**，GDI+ 画不出半像素 |

### 3.2 圆角档位（只能取这几档）

| token | 值 | 用途 |
|---|---|---|
| none | 0 | 贴边容器、连体按钮中段 |
| xs | 2px | 极小指示器 |
| sm | 4px | 输入框、chip、紧凑按钮 |
| md | 6px | 标准按钮、toast |
| lg | 8px | 浮层菜单、面板内部模块 |
| xl | 12px | 内容卡片 |
| 2xl | 16px | 顶层浮层（手机端抽屉上沿） |
| full | 9999px | 头像、胶囊标签、开关 |

### 3.3 同心圆角公式（必算）

$$R_{outer} = R_{inner} + Padding$$

容器 16px 内边距 + 内部 6px 圆角 → 外层应为 22px（取 20 或 24）。内外圆角相等会让内角看起来"尖"。
WinForms 自绘圆角矩形时同理，别内外都用同一个半径。

### 3.4 光学重心

图标 + 文字并排时，图标下移 `0.125em`（约 1–2px）再对齐，别用绝对居中。
弹窗垂直位置固定在视口 **38.2%**，不要正中 50%（正中会有下坠感）。

## 4. 阴影

### 4.1 页面默认平

**这是最重的 AI 味来源**：给每个卡片挂阴影、外发光。规则：

- 常规面板、列表容器、卡片 → **纯平**，用 0.5px 微边框和 `--raised` 底色分层
- 阴影**只给真正离屏的浮层**：下拉菜单、抽屉、模态、批量操作浮条
- WinForms：`Form` 的 `DropShadow` 只给对话框，主窗体不加

### 4.2 阴影被裁切的硬门禁

容器有 `overflow: hidden/auto`（WinForms 的 `AutoScroll`、手机端抽屉的滚动区）时，
内部元素的阴影会被切一半。判据：

$$\text{外周留白} \ge \text{OffsetY} + \text{Blur} + \text{Spread}$$

不够就把阴影提到外层无裁切容器，或干脆降级成微边框。

## 5. 间距

只用 4 / 8 / 12 / 16 / 24 / 32 / 48。不写 5、7、13、17 这种奇数值。

| 值 | 用途 |
|---|---|
| 4 | 图标与文字、行内小间隙 |
| 8 | 紧凑行距、按钮内边距、列表项内部 |
| 12 | 表单项之间、紧凑卡片内边距 |
| 16 | 标准容器内边距、列表列间距 |
| 24 | 区块之间、浮层内边距 |
| 32 | 大模块分隔、空状态留白 |
| 48 | 主内容区与导航的大留白 |

## 6. 字号：严格 4 档

| 档 | CSS | WinForms | 用途 |
|---|---|---|---|
| 大数字 | 24 / 28 | 18pt Semibold | KPI、倒计时、坐标大数 |
| 模块标题 | 16 / 24 | 12pt Semibold | 面板标题、弹窗标题、"任务 · 3" |
| 正文 | 14 / 20 | 10.5pt Regular | 任务名、物品名、表格数据 |
| 辅助 | 12 / 16 | 9pt Regular | 副标题、坐标、时间戳、状态标签 |

**禁止**出现 13px、15px、11px 这种只差 1–2px 的层级——那就是"没层级"。

### 6.1 暗色模式字重补偿

黑底白字会因为光晕扩散看起来**比浅色粗 10–15%**。暗色界面的字重要主动降一档：
`Semibold(600) → Medium(500)`，`Medium(500) → Regular(400)`。
WinForms 用 `FontStyle.Bold` 的地方，暗色下多数应该改成 `Graphics.DrawString` + 常规字重加亮色，
或者至少别在 14px 以下用 Bold。

### 6.2 等宽数字

所有会跳动的数字（坐标、坐标轴刻度、任务数、计时、物品数量）必须：

- CSS：`font-variant-numeric: tabular-nums`
- WinForms：`TextFormatFlags.NoPadding` + 固定宽度绘制，或用等宽字体（Consolas）

否则数字从 9 跳到 10 会横向抖一下。

### 6.3 行高与换行

- 行高 ≥ 1.5（`line-height: 1.5`），多语言/长中文才不会挤
- 关键标题用 `text-wrap: balance`，避免末行孤字
- **禁止用 `overflow: hidden` 去"修"排版**——那是把内容切掉，不是排版

## 7. 操作区纪律（我们目前最大的问题）

### 7.1 主操作唯一

一个独立操作区**最多 1 个 Primary 按钮**（实心 `--accent`），其余全部是次级（描边或纯文字）。

现状检查（顶栏）：`撤离点 / 图层 / 刷新数据 / 复位 / 瓦片版 / 手机端` 是 6 个等权按钮，
没有主次。按规范应该是：**1 个主操作**（建议"手机端"或"图层"，看使用频次）+ 其余降为次级。

### 7.2 严肃二选一必须中立

"通过 / 驳回"这类对立操作**都不给主色**，不诱导点击。

### 7.3 危险操作加阻力

删除、清空、扣费必须走确认框：

- 标题中立交代对象（"清空本图已完成标记？"）
- 描述写清不可逆后果（"共 12 条，清空后无法恢复"）
- 按钮用动宾明确文案（"彻底清空"，不是"确定"）

现状：图层菜单里的「清空已完成标记」目前是**直接执行**，违反本条，应补确认框。

### 7.4 选型判据

| 选项数 | 用什么 |
|---|---|
| 2–4 | 平铺单选 / 分段控件 |
| 立即生效的布尔 | 开关（Switch） |
| > 5 | 下拉 / 搜索下拉 |
| 多选且要一眼看全 | 复选列表（不要塞进下拉） |

## 8. 浮层：Modal vs Drawer

| 场景 | 用什么 |
|---|---|
| 查看详情、轻编辑、保留列表上下文 | **侧边抽屉**（手机端已有底部抽屉，电脑端可用浮层） |
| 独立填报、需专注 | 独立页 / 大弹窗 |
| 打断确认、危险操作 | 居中 Modal（垂直 38.2%） |

**表单弹窗必须 `maskClosable = false`**：点遮罩不关，防止手滑丢输入。
有脏数据时离开要拦截（手机端抽屉现在没有脏检查，将来加编辑功能时注意）。

**模态 ≠ 阻断**：能用抽屉看的东西不要弹居中框。

## 9. 数据展示

- **三向对齐**：文本左、数值与时间右、复选框/图标居中。金额和计数右对齐后才能竖直对齐
- **五态齐全**：任何数据区都要有「理想 / 空 / 加载 / 错误 / 受限」五态
  - 空态必须写**为什么空** + 给出口（"本图没有进行中的任务 · 点右上『任意地区』查看"）
  - 现状：任务列表空态只有一行字，缺出口
- **查询分层**：基础筛选平铺 ≤ 4 个；重查询给显式"查询"按钮，不要每改一个字就全量重算
  （我们这边对应：切图层/切地图时不要每次都重拉网络数据）
- **时间胶囊外露**：今天 / 近 7 天这类高频区间做成可见胶囊，不要藏进下拉

---

## 10. 可读性与触控

- 对比度：正文 ≥ 4.5:1，辅助文字可以放宽但**不能低于 3:1**
- 手机端触控目标 ≥ **44×44 px**（现在 30px 高的 chip 偏小，点击误差大）
- 手机端行高 ≥ 1.5；不要用 `overflow:hidden` 削字
- 安全区：`env(safe-area-inset-*)` 必须留给刘海和底部横条（已做）

---

## 11. 禁止手搓轮子

浮层、下拉、折叠、日期选择**不要用裸 div 从零拼**。本项目里：

- 手机端没有框架，但**抽屉/下拉/确认框**应各只有一份实现，复用，不要每个功能抄一遍
- 电脑端优先用 WinForms 原生控件或已有自绘组件，别为一个小浮层再写一套

## 14. 改规范的流程

1. 想加新颜色 / 新圆角 / 新字号档 → **先改本文件 §2、§3、§6**
2. 同时改两处实现：`Assets/mobile/app.css` 的 `:root` + `UiTokens.cs`
3. 截图对比，按 §12 走查
4. 规范与代码不一致时，**以本文件为准并修代码**，不要反过来改规范迁就代码
