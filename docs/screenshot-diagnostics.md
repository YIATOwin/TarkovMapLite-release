# 截图定位故障排查

主窗口底部“测试截图”可读取目录中最新的有效坐标截图，忽略启动时间限制，并按当前浏览地图预览。截图本身不包含地图名；自动定位需要游戏日志识别对应地图，手动测试可以帮助区分这两条链路。

右键“测试截图”打开诊断窗口，可以刷新、复制或保存文本。报告包括程序版本、轮询是否运行、最后扫描时间、截图时间下限、文件筛选数量、日志目录和地图绑定，以及最近 12 个 PNG 的文件名和时间；不读取截图图像。诊断文件包含本机目录和游戏坐标，保存后由用户自行决定如何提供。

本次在模拟文件与应用窗口中复现并修复：

- 最新 PNG 不带坐标，遮住较早但有效的截图；旧代码下一轮还会把解析失败状态改回等待或已定位。
- 某张文件的修改时间在未来，持续被选为最新截图，重启也无法恢复。
- 同一路径被重写，但只按路径去重，没有观察修改时间和长度。
- 坐标或四元数采用科学计数法（例如 `-2.87E-05`）而旧正则仅接受普通小数。
- 开始轮询前等待联网任务刷新，下载期间不处理截图，随后又把时间下限改为下载结束时间。
- 新地图事件经消息队列延迟执行，或者迟到的日志回放没有发布进图事件，造成时间下限/地图绑定错误；新对局没有清空旧 Current 也会出现错误复用。
- 测试截图已读到新坐标，但旧真实定位优先，导致按钮预览没有实际更新。
- 日志文件被截断后，读取偏移仍指向旧文件末尾。

仍需要故障机器诊断才能确定实际原因。目录正确不代表文件筛选、时间、文件名与日志地图都正确。若底栏显示“已读到截图，等待游戏日志识别地图”，截图读取已成功，应检查报告中的日志目录及地图绑定。若最后轮询时间停止变化，优先检查轮询/界面阻塞；若轮询在更新而位置截图时间不变，检查最近文件的解析结果和筛选原因。

验证：截图专项测试通过，覆盖重启、时间异常、无关 PNG、科学计数法、覆盖写入、对局切换、迟到日志、手动预览、诊断和日志截断。游戏不在本机，尚未对故障机器实机复测。
