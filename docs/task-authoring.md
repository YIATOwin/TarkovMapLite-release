# 手工维护任务与点位

主窗口底部打开“任务维护”。左侧搜索任务，右侧分为任务、目标、点位 / 区域、修订 JSON 四页。

## 常用操作

1. 修改已有任务：选中任务，编辑名称、商人、等级、阵营和必需性；未知值保留“未知”。
2. 新增任务：点“新增任务”，在“修订 JSON”中把 `manual-…` 改成游戏真实任务 ID，可以匹配游戏日志。不知道 ID 时仍可用临时 ID 浏览，但不会自动匹配日志。
3. 编辑目标：在“目标”页添加目标和描述，填写类型、数量、物品 ID；钥匙组是二维 ID 数组，如 `[["钥匙ID"]]`。目标 ID 必须稳定，同一目标的点位填同一个 ID。
4. 标点：先选目标行，再选地图与楼层，打开“右键添加点位”，在地图上右键。左键拖动标记移动点位；中键或空白处拖动平移，滚轮缩放。
5. 区域：在“点位 / 区域”页选择位置，编辑下方的世界 X/Z 顶点，可新增、删除顶点（至少三个）。拖动标记移动整个区域。楼层按该地图的编号填写，地面为 0、地下通常为 -1；从楼层下拉添加的新点会自动填写。其它楼层在维护地图上半透明显示。
6. 保存：写入本地修订文件并立即更新主窗口。关闭窗口时提示未保存草稿；每次覆盖已有文件前保留 `.bak`。
7. 撤销此任务修订：删除该任务的本地修订草稿；保存后已有任务恢复接口数据，纯手工任务移除。若修订来自 exe 内置文件，需要修改仓库中的内置文件。

“修订 JSON”支持直接编辑整个补充文件；修改后必须先“校验并应用 JSON 到草稿”，再保存。校验失败保留原文件。直接编辑磁盘文件后，可重新打开并保存以应用；应用启动时也会读取该文件。

## Git 工作流

- “另存为”可以直接保存到 Git 工作目录中的 `task-overrides.json`，之后自行提交、推送。
- 其他电脑可打开下载后的文件并保存，或使用“从 Git 地址读取”填写 GitHub Raw / GitHub Pages 的公开 HTTPS JSON 地址，读取成功后再保存生效。读取失败不替换原草稿。当前版本由用户手动触发同步。
- 如需让修订跟随 exe 发布，把校验后的文件放到本仓库 `Assets/task-overrides.json`，它会编入程序。
- 也可把文件放在 exe 旁边的 `Assets/task-overrides.json`，作为资源覆盖文件使用。

加载优先级：接口/缓存任务 → 随 exe 的任务修订 → 用户选中的本地修订。接口刷新不会写回手工修订文件。
修订文件没有包含的任务保持原数据；任务内部的 `obj`、`zones` 数组表示整体替换。`zones: []` 明确清除该任务所有位置，不再被旧坐标快照补回。不要把未修改任务全部复制进补充文件，否则会固定它们的上游数据。

默认本地文件位于 `%LOCALAPPDATA%\TarkovMapLite\task-overrides.json`。另存到其它位置后记住该路径。文件损坏时继续使用基础数据，可在维护窗口查看错误、修复文件；覆盖前也会备份损坏文件。

## 文件结构

```json
{
  "schema": 1,
  "tasks": [
    {
      "id": "游戏任务ID",
      "name": "手工修订的任务名称",
      "source": "来源或校准说明",
      "zones": []
    }
  ]
}
```

可选字段：`trader`（商人 ID）、`wiki`、`slug`、`meta`、`obj`、`zones`。未提供的字段继承基础数据。元数据字段沿用内置格式：`Regions`、`RegionKnown`、`MinLevel`、`Faction`、`Kappa`、`Lightkeeper`，未知使用 `null`。

每个区域包含 `m`（标准地图 key）、`t`（目标类型）、`o`（目标 ID）、`f`（楼层）、`floorKnown` 和 `p`（世界 X/Z 顶点数组）。界面添加的单点使用 8×8 世界单位的小方框保存，并标记 `point: true`；它只是显示标记，不表示真实任务触发范围。坐标使用游戏世界坐标，不能直接填其他网站的 SVG 像素坐标。

暂不自动推送 Git，也不推断任务是否已解锁；主线剧情数据仍由原主线数据文件管理，本维护窗口面向商人任务。
